## 本周目标

第三周我完成了一个单轮的学习计划 Agent。它可以识别目标、拆出步骤、调用本地工具、记录执行轨迹。这周继续沿着这套结构向前推进，重点放在运行状态的保存和任务之间的关系。

我希望这周的 Agent 能回答三个实际问题：当前计划完成到哪里了，下一步有哪些任务可以执行，关闭程序后能不能从原来的位置继续。围绕这三个问题，我完成了一个带持久化会话的学习计划 Agent，项目目录为 `ai-learning-week4-agent-session`。代码和测试放在第四周项目仓库中，博客副本也放在仓库的 `blog` 目录。

## 学习内容

### 从单轮执行到持续会话

第三周的记忆保存在 Python 对象里，程序结束后，目标、工具调用和结果都会消失。这种短期记忆适合观察一次运行的轨迹，学习计划通常需要多次投入时间，所以这周加入了 JSON 会话文件。

会话文件保存四类信息：

- 原始学习目标和创建时间
- 任务列表、工具、参数和前置任务
- 每个任务的状态、尝试次数和最终结果
- 工具调用事件、成功结果和错误文字

程序启动时读取 JSON，执行后写回同一个文件。保存格式保持扁平，阅读文件就能知道当前计划发生过什么。以后切换到数据库时，`Session` 的字段也能继续复用。

### 任务依赖决定执行顺序

单纯把任务放进列表，程序可以按顺序调用工具。学习计划里常见的关系是先完成目标整理，再建立清单，接着安排时间，最后生成复盘提醒。于是每个任务有一个 `depends_on` 字段。

当前项目有四个任务：

```text
t1 明确本周目标
  ↓
t2 建立学习清单
  ↓
t3 安排时间预算
  ↓
t4 生成复盘提醒
```

`Session.ready_tasks()` 会查找状态为 `pending` 且所有前置任务都已经完成的任务。每次运行只处理当前可运行的任务，下一次运行继续从新的边界开始。这个设计让执行顺序由状态和依赖共同决定，计划结构也能直接显示给使用者。

### 工具接口和参数校验

Agent 仍然通过工具注册表选择能力。这周保留了第三周的摘要和清单工具，新增时间预算和复盘提醒工具。

`time_budget()` 从结构化参数中读取小时数。输入包含 6 小时时，工具给出总时长、建议天数和每天投入时间。小时数为 0 或超过一周总小时数时，工具抛出 `ToolError`。`review_prompt()` 根据目标生成复盘问题，帮助使用者记录有效做法和待改进点。

工具只处理白名单中的输入。Agent 可以选择工具和传入参数，工具内部仍然负责校验。这样便于单独测试，也能把错误记录回任务。

### 失败重试和可观察事件

外层执行器为每个任务设置最多两次尝试。工具成功后，任务状态写为 `done`，结果保存到任务和事件中。工具失败后，事件保存 `error` 状态和错误文字，任务再次尝试；两次都失败时，任务状态写为 `failed`，执行循环停止，等待下一次检查输入。

这套机制提供了几个可观察字段：

- `attempts`：任务已经尝试了几次
- `status`：`pending`、`running`、`done` 或 `failed`
- `result`：最近一次成功结果
- `error`：最近一次失败原因

有了这些字段，复盘可以定位到具体任务。输出中的完成率和工具成功率也有明确来源，计算过程可以直接从会话文件重现。

### 复盘指标

这周加入了一个轻量的 `review()` 函数。它计算已完成任务数除以任务总数得到完成率，计算成功事件数除以工具调用事件数得到工具成功率，并根据状态给出下一步建议。

指标只描述本次会话里的事实。完成率为 100% 时，建议把复盘结果写入下一次学习计划；存在失败任务时，建议先检查输入；还有待执行任务时，建议继续运行可执行任务。

### 初始化一份学习会话

我使用下面的命令创建会话：

```powershell
python -m src.agent init '本周学习 agent，安排 6 小时并完成工具调用练习' --session outputs/session.json
```

初始化后，四个任务都处于 `pending`。任务依赖写入文件，t1 没有前置任务，t2 依赖 t1，t3 依赖 t2，t4 依赖 t3。

### 分次运行并恢复状态

第一次执行：

```powershell
python -m src.agent run --session outputs/session.json
```

第一次运行完成 t1，第二次运行完成 t2，后面两次分别完成 t3 和 t4。每次运行结束，`Session.save()` 都把新的任务状态、事件和时间写回 JSON。关闭终端后重新运行，程序读取文件中的状态，已经完成的任务不会重复执行。

这次实际运行的目标是本周学习 agent，安排 6 小时并完成工具调用练习。四个任务各执行一次，最终进度输出为：

```text
完成率：100%
t1 明确本周目标，状态 done，尝试 1
t2 建立学习清单，状态 done，尝试 1
t3 安排时间预算，状态 done，尝试 1
t4 生成复盘提醒，状态 done，尝试 1
```

复盘命令：

```powershell
python -m src.agent review --session outputs/session.json
```

得到的两个指标都是 1.0，说明这次会话中的四次工具调用全部成功。复盘建议提示把结果写入下一次学习计划。

### 测试重点

项目使用 Python 标准库的 `unittest`，共五个测试：

1. 检查规划结果包含正确的依赖关系
2. 检查会话保存后可以恢复，并按依赖分次继续执行
3. 检查复盘可以计算完成率和工具成功率
4. 检查无效小时数会被工具拒绝
5. 检查未设置 API Key 时，大模型规划会回退到规则规划

测试命令：

```powershell
python -m unittest discover -s tests -v
```

实际运行结果为 5 个测试全部通过。测试覆盖了这周新增的持久化、依赖和复盘逻辑，也保留了工具参数的边界检查。

### 这次实现遇到的问题

第一次运行时，所有任务都显示为 `pending`，原因是命令还没有执行。执行一次 `run` 后，只有没有前置任务的 t1 进入 `done`，这符合依赖设计。后续任务需要在下一次运行中逐层释放，进度输出可以清楚地显示这个过程。

另一个细节是 `Session.load()` 需要把 JSON 字典重新转换成 `Task` 和 `Event` 对象。直接使用字典会丢失 `ready_tasks()`、`completion()` 等方法。当前加载函数完成了这层转换，保存和恢复测试也验证了这一点。

## 本周真正理解了什么

这周我把第三周的单轮 Agent 延伸成了一份可继续推进的学习会话。Agent 的重点从一次规划和一次工具调用，扩展到状态保存、依赖判断、失败记录和复盘指标。任务状态让程序知道已经完成什么，依赖关系让程序知道现在能做什么，事件记录让程序能解释为什么得到这个结果。

当前版本仍然使用规则规划器和本地工具，运行过程可以离线复现。后续接入真实模型时，模型可以负责提出任务草案，程序继续负责校验任务结构、检查工具参数、保存状态和统计结果。我下一步会准备一组固定学习目标，比较不同目标下的规划结果，并加入人工确认步骤。

### 简单接入大模型规划

在原有规则规划器之外，我增加了一个可选的 OpenAI Responses API 规划器。命令行使用 `init --llm` 时，程序把学习目标发送给模型，请模型返回任务数组。每个任务必须包含编号、标题、动作、工具、参数和前置任务，工具只能从项目已经注册的四个工具中选择。

调用前需要在 PowerShell 中设置环境变量：

```powershell
$env:OPENAI_API_KEY = '你的 API Key'
$env:OPENAI_MODEL = 'gpt-5-mini'
python -m src.agent init '本周学习 RAG，安排 6 小时并完成一个检索练习' --llm --session outputs\llm-session.json
```

程序使用标准库 `urllib` 请求 `https://api.openai.com/v1/responses`，请求体包含模型、系统说明、用户目标和 `store: false`。模型规划结果先经过 JSON 解析，再检查任务数量、工具白名单和依赖是否存在。检查通过后才写入本地会话。

这次接入保留了规则规划作为回退路径。没有 `OPENAI_API_KEY` 时，命令会提示模型规划不可用并继续使用规则规划；请求超时、网络错误或 JSON 格式错误也走同一条回退路径。这样可以在有 API Key 时观察模型规划，在离线环境里继续运行同一个项目。

这一步让我看到模型在 Agent 中承担的职责：模型负责把自然语言目标转换成结构化计划，程序负责校验计划、执行工具、保存状态和统计结果。模型输出没有直接获得文件系统或 shell 权限，工具边界仍然由代码控制。

本地测试覆盖规则规划、会话恢复、复盘指标和参数校验。没有 API Key 的 `--llm` 命令也完成了回退验证。真实模型调用需要用户自己的 API Key 和网络环境，当前仓库没有保存任何密钥。

### 第五周计划：做成可视化 Web 应用

第五周准备给这个 Agent 加一个本地 Web 界面。页面提供学习目标输入、规则规划与模型规划切换、任务依赖图、逐步执行按钮、进度指标和工具调用时间线。界面直接调用现有的 `Session`、`Planner`、`run_session()` 和 `review()`，每次操作后读取并保存同一份会话文件。先完成单用户本地版本，再检查重复点击、失败任务和刷新页面后的状态恢复。项目完成后，用几组固定目标演示从创建计划到复盘的完整过程。
