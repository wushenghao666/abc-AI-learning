第五周把学习 Agent 接到了浏览器上，可以查看规划、工具调用和会话状态。这周回到原来八周计划中的 RAG。我想让程序查询已经写过的学习记录，回答第四周如何恢复会话、第五周为什么更换接口这类问题。

第六周和第七周共同完成一个个人学习资料问答项目。本周先把本地流程、检索实验和回答评估做清楚，第七周再继续完善 Web 应用与公网部署。10.25 这次交付先留在本地，代码、资料快照、实验结果和博客都保留了 Git 记录。

## 先把问题分成两步

最初很容易把注意力放在模型最后说了什么。实际做下来，我需要先检查程序找到了什么，再检查回答怎样使用这些资料。

这周固定了两个问题：程序能否找到相关依据；程序能否依据这些内容给出正确、引用充分的回答。检索漏掉关键章节时，换一个模型也未必能补回来。检索已经命中时，模型仍可能拒答、遗漏条件或把周次写错。

因此，项目分别保存检索片段、相似度、模型原始输出和校验结果。接口返回文本只算请求成功，回答质量另外评估。

## 从十份资料开始

### 限定导入范围

前五周已经有博客、README、源代码、运行输出和会话文件。本周先导入五篇学习博客和五份项目 README，共十份 Markdown。八周学习计划用来核对方向，暂时没有放进问答资料库。

导入程序按清单读取这十个文件，避开环境配置、密钥、Git 内部文件、会话记录和生成输出。博客与 README 内容有重复，也有旧说明，我都保留在快照里。例如第五周 README 仍有模型可以返回两到五个任务的旧文字，博客后面的修复记录则要求四种工具各出现一次。这种差异适合检查程序能否分辨时间和上下文。

每份资料记录原始相对路径、标题、所属周次和 SHA-256。切分后的片段继续保留章节、原文起止字符和编号，回答中的依据可以一路找到原文件。

```text
data/
├─ raw/             十份资料快照与来源清单
└─ index/           片段元数据与向量，运行命令重建
```

原始资料随仓库保存，索引和模型权重单独管理。这样拿到项目后，可以直接用快照建立索引，也能重新从前五周目录导入。原来的项目内容保持原样。

### 按章节切分

这次先按 Markdown 标题拆章节，再把较长章节切成最多 480 字符的窗口，相邻窗口重叠 80 字符。窗口后段尽量在换段或句末结束，代码围栏内的井号按代码处理。

当前十份资料一共生成 112 个片段。480 是字符数，向量模型另有 512 token 的输入上限，两者需要区分。标题、周次和章节也参与编码，实际过长输入会截断，因此片段本身保留得比较短。代码记录完整原文，方便检查截断与检索结果。

## 先确认模型平台能做什么

第五周用的是并行科技的 GLM-4-Flash。这周需要生成模型和向量模型，两种能力分别检查。

最初本地没有密钥，模型列表、生成和向量接口都返回 HTTP 401。这个结果只能说明缺少认证。配置后再次检查，GLM-4-Flash 能返回文本；用 BGE 模型名请求平台向量接口得到 HTTP 400；账户模型列表中的 GLM-Embedding-3 则实际返回了 2048 维向量。

本周最终使用本地 BAAI/bge-small-zh-v1.5 生成向量，后端调用平台生成回答。这样没有密钥时仍能建立索引和检索。BGE 使用固定模型版本、CLS 池化和 L2 归一化，向量维度为 512；问题前加上模型推荐的中文检索指令，资料正文不加。用法参考了 [BGE 模型说明](https://huggingface.co/BAAI/bge-small-zh-v1.5)。

索引直接保存为 NumPy 矩阵，查询时计算余弦相似度。这批资料规模很小，精确计算已经够用。向量模型或资料发生变化时，程序会要求重建索引，避免把新问题向量与旧空间混在一起。

生成端先沿用 GLM-4-Flash，后来根据实际失败又测试了账户中可用的 GLM-4.5-Flash。最终配置采用后者，temperature 为 0，最多输出 2400 token，超时 60 秒，并使用 thinking=disabled。关闭思考的参数参考了[模型接口说明](https://docs.bigmodel.cn/cn/guide/models/free/glm-4.5-flash)，是否能调用仍以这次平台实测为准。这里记录的是接口模型标识，底层权重由供应商提供。

密钥只放在本地被 Git 忽略的后端配置中。前端没有填写或读取密钥的入口，报告只保存参数、结果与脱敏错误。

## 用同一组问题比较检索

### 固定二十四道题

评估集覆盖了几类实际问题：单篇资料查询、跨周比较、同一问题换一种表达、资料中没有答案，以及容易混淆的能力边界。每题都写了预期依据或判断标准。

例如，第四周怎样实现会话恢复，与关掉程序后怎样接着做，表达不同，核心都指向持久化与依赖执行。第五周是否有用户登录，需要找到明确的能力边界。数据库连接池大小、平台密钥和 A100 训练时长，则应该承认资料不足。

其中 21 题在资料库中有答案，3 题没有答案。检索分数按预先选定的文件和原文锚点计算，跨周题需要找齐全部依据组。无答案题保留检索结果，但不放进依据命中率的分母。

### 关键词在这批资料里更占优势

关键词方案使用中文连续双字词和英文、数字词，再用 BM25 排序。向量方案使用同一套片段和本地 BGE。进一步选择检索片段数量 k 做参数实验，其他配置固定。

| 检索方式 | 取 2 段 | 取 4 段 | 取 6 段 |
| --- | ---: | ---: | ---: |
| BM25 指定依据完整命中 | 13/21 | 16/21 | 16/21 |
| BGE 指定依据完整命中 | 9/21 | 11/21 | 13/21 |

关键词从两段增加到四段，多找齐了三题；继续增加到六段，没有新增完整命中。向量从两段增加到六段，多找齐了四题，但总体仍低于关键词。

这批资料里有很多函数名、周次、平台名和具体错误，字面匹配很有帮助。结果让我放下了向量一定更好的预期，也提醒我先看当前语料的实际表现。

这套锚点评分也有局限。第四周博客会回顾第三周的内存行为，即使没有命中第三周原文，也可能已经找到等价依据。我没有为了提高分数修改锚点，另外在逐题审阅里说明这些情况。

### 把两路结果合起来

之后增加了 RRF 组合检索：分别取关键词和向量的前十二名，按排名合并，再去掉同一资料中高度重叠的窗口。排名合并可以避开两种分数尺度不同的问题。

| 组合检索 | 取 2 段 | 取 4 段 | 取 6 段 |
| --- | ---: | ---: | ---: |
| 指定依据完整命中 | 11/21 | 15/21 | 17/21 |

最终本地入口默认使用组合检索、取六段。它在这套问题中找齐的依据更多，代价是模型需要读更多文本。当前结果只支持这批资料下的选择，后续增加资料后还需要重测。

## 引用怎样对应到原文

第一版让模型自己写结论，同时抄出引文，再检查引文是否真的出现在对应检索片段中。这个检查找出了具体问题：模型会删去换行和列表符号，也会把两句不连续的原文拼在一起。

组合检索的一次会话恢复回答就把多行保存字段改写成一句话。作品集回答也拼接了并不连续的原文。意思看起来接近，逐字核对时都无法通过。程序保留了原始输出，并显示引用校验失败。

后来我把引文改为程序预先划好的原文单元。每个检索片段内，按句末和换行生成最长 180 字符的连续单元，各自带有编号。模型只选择资料编号和单元编号，程序按编号取回原文，页面显示文件、章节和支持片段。

这样减少了模型抄写 Markdown 的负担。最终二十四题都通过了编号和原文追溯校验。不过，引文存在与引文支持结论仍然有差别，后面的逐题检查又发现了语义问题。

资料内容始终放在待查询证据中，不能修改系统规则。问答后端没有向模型提供 shell、文件修改等工具权限，资料里的命令只作为文本显示。模型建议与资料事实也分开展示。

## 接口成功后，继续检查答案

初轮采用 GLM-4-Flash 和向量检索四段，最终采用 GLM-4.5-Flash、组合检索六段及编号引文。两轮都实际运行了全部二十四题，原始结果逐题保存。

| 指标 | 初轮 | 最终 |
| --- | ---: | ---: |
| 收到真实模型文本 | 24/24 | 24/24 |
| 结构和引用追溯校验通过 | 23/24 | 24/24 |
| 回答语义正确 | 15/24 | 21/24 |
| 所选引文支持全部事实 | 12/15 | 17/20 |
| 正确且引用充分，或正确拒答 | 14/24 | 19/24 |
| 无答案题正确拒答 | 3/3 | 3/3 |

引用支持率只统计通过结构校验且包含事实的回答，因此分母与总题数不同。最终四题返回资料不足，其中一道原本有答案。接口成功率达到 100%，回答和引用仍有失败。

语义与引用支持由本次开发助手逐题审阅，标准和理由都保存在项目里，尚未经过独立人工复核。这组题也参与了开发，不能当作独立测试集。最终同时调整了检索、模型、提示和引用格式，表格反映的是两套完整流程的差异。前面的 k 对比才是控制其他条件的参数实验。

最终这轮接口返回的总用量为 51,707 token，初轮为 24,926 token。上下文更多、输出更长，质量改善也伴随着更多用量。本周没有根据用量推算费用。

## 还留下了哪些失败

### 跨周比较没有回答完整

初轮把第四周新增的持久化、依赖和复盘写成了第三周的能力。增加周次字段和提示后，最终回答避开了这次归因错误，但仍主要描述第五周新增的 Web 功能，没有完整说明第三周到第五周的演进。这题继续记为失败。

### 资料中有答案，程序仍可能拒答

关于 Session.ready_tasks() 的题目，组合检索前六段没有包含完整条件，模型返回资料不足。资料里实际写了 pending 状态与所有前置任务完成的条件，整个问答任务因此没有完成。后面可以尝试按函数名检索、章节重排或拆分跨周问题，这些方向本周还没有验证。

### 真实引文也会被解释错

旧说明比较题中，模型把曾输出八个任务、超过允许数量，写成了旧版本允许八个任务。它还漏掉 README 中两到五个任务的旧文字。编号和引文都是真实的，结论却与原文相反，这题的回答和引用支持都没有通过。

另有两题回答内容正确，引用覆盖仍不够完整：CNN 对比选取的表格行没有明确带上完整训练集、十轮的实验条件；混淆矩阵回答的附加结论引用了指向每类召回率的文字。它们提醒我，引用也需要检查对象和限定条件。

无答案题这轮三题都正确拒答，样本仍然很少。当前没有使用经过独立校准的相似度拒答阈值，不能凭这三题就认为程序能处理所有资料不足情况。

## 本地运行和交付

项目放在 week 6 目录，使用独立虚拟环境。现有快照可以直接建索引，重新导入与运行的主要命令如下：

```powershell
.\.venv\Scripts\python.exe -m src.cli import --source-root 'C:\Users\wushe\Documents\ChatGPT'
.\.venv\Scripts\python.exe -m src.cli index
.\.venv\Scripts\python.exe -m src.web
```

打开 http://127.0.0.1:8006/，输入问题后可以选择关键词、向量或组合检索。页面默认只检索，取消勾选后调用真实生成模型。没有密钥时仍能查看检索片段，真实请求失败会展示具体错误。

本地页面随后补充了六个示例，每个都有预期结果和依据，也加入检索方式、片段数与只检索的解释。查询时可以实时查看关键词排名、向量编码、两路合并、上下文、脱敏 API 请求与返回、引用校验。这里展示程序实际记录，模型仍采用完整响应，内部思维链不展示。补充验证中，平台实际返回过 HTTP 429 速率限制，页面保留了已经完成的检索过程和具体错误。

### 在本机同时预览应用和博客

问答应用使用 8006 端口，博客预览使用 8007 端口，两者分别启动。先在应用中试一个示例，观察预期结果、检索排名与原文，再回到博客对照实验记录，会更容易理解每个数字对应哪一步。

博客使用 Markdown 保存文章，运行 build.py 后生成页面读取的 posts.json 索引，再启动静态文件服务：

```powershell
Set-Location 'C:\Users\wushe\Documents\ChatGPT\AI-learning'
& 'C:\Users\wushe\Documents\ChatGPT\week 6\.venv\Scripts\python.exe' build.py
& 'C:\Users\wushe\Documents\ChatGPT\week 6\.venv\Scripts\python.exe' -m http.server 8007 --bind 127.0.0.1
```

打开 http://127.0.0.1:8007/#post=2026-10-25-personal-rag 即可预览本篇。文章和配图都保存在本地；修改正文后刷新页面，修改标题或摘要后需要重新生成索引。

模块分别负责资料、向量、检索、生成、应用入口和 HTTP 适配，命令行、页面与评估共用同一套问答服务。完整交互、会话管理和公网部署留给第七周。

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe scripts\evaluate.py --include-hybrid --name repeat-retrieval
.\.venv\Scripts\python.exe scripts\evaluate.py --answers --method hybrid --k 6 --name repeat-answers
```

首版 28 项自动测试全部通过，覆盖资料加载、索引失效、空输入、无匹配、引用编号与原文、模型超时和请求失败，以及本地 HTTP 边界。补充示例与过程展示后，回归扩展到 34 项并全部通过，增加了实时事件顺序、API 字段过滤、失败过程保留和示例资源检查。测试中的合成向量只用于隔离程序逻辑，前面的实验使用真实 BGE 和真实模型接口。中间失败的输出、小模型的探索记录和中断前的已完成样例也一并保留。

这一周让我把 RAG 拆成了可以分别检查的环节。找回资料、组织上下文、生成回答、核对引用，各自都会出问题。现在项目已经能查询自己的学习记录，也能把失败定位到具体片段与结论。第七周继续做应用时，我会保留这些检查入口，先处理当前的跨周检索和旧说明判断，再完善使用体验。
